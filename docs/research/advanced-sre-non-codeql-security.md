# GitHub security review and Autofix beyond CodeQL

Research date: **2026-10-28**. Scope: [Verify GitHub review security and Autofix beyond CodeQL languages](https://github.com/JoranBergfeld/sre-agent-workshop/issues/76), supporting [Map: Advanced SRE Agent context engineering and secure coding handover](https://github.com/JoranBergfeld/sre-agent-workshop/issues/70).

Product-capability research, not a vulnerability assessment. No repository security scan, exploit, deployment, language selection, or scenario implementation was performed. Sources below are first-party product documentation, release announcements, and scanner-maintainer documentation. Private repository content was not submitted to third-party services. “Documented” means supported by these sources, **not demonstrated in an exercised workshop fixture**.

## Executive finding

**A native non-CodeQL detection-to-Copilot-Autofix path now exists.** GitHub's **AI Scan for pull requests** is generally available, explicitly covers PHP, Shell/Bash, Terraform HCL and Dockerfiles, and can attach **named Copilot Autofix** suggestions to findings. “Autofix only works with CodeQL languages” is no longer an accurate blanket statement. AI Scan does not require CodeQL default setup or a Copilot license. It does require code scanning, effective AI Scan enablement, an eligible repository/PR, and available Code Security AI Credits. [S3][S4][S5]

This makes **PHP, Bash, and Terraform HCL** a small evidence-backed feasibility shortlist, with different roles: application, operations script, and infrastructure configuration. It does **not** make a deterministic, mandatory finding-and-fix exercise proven. AI detection and fix generation are best-effort; AI Scan is PR-only, excludes fork-origin and Dependabot-created PRs, and cannot enforce merge blocking. The cloud agent's own automatic CodeQL validation still cannot analyze these languages. [S1][S3][S6]

## 1. Establish the CodeQL boundary first

The current GitHub documentation lists these supported CodeQL language groups:

- C/C++
- C#
- Go
- Java/Kotlin
- JavaScript/TypeScript
- Python
- Ruby
- **Rust**
- Swift
- **GitHub Actions workflows**

The CodeQL language/compiler reference corroborates these groups. Rust is not a valid “outside CodeQL” choice: Rust support became GA on **2025-10-14**, with Copilot Autofix recommendations. GitHub Actions YAML support is not support for arbitrary YAML, Bash scripts, PowerShell, Terraform, or every language embedded in a workflow. PHP is explicitly unsupported by CodeQL; Bash, HCL, Dockerfile, PowerShell, Dart, Elixir, and Scala are outside the current language list. Framework gaps within Java/C# are a separate question from an unsupported implementation language. [S1][S2][S7]

## 2. Recent developments that change the answer

[S8] | Even historically, “CodeQL only” had an exception. This is not permission to assume arbitrary SARIF tools/languages are supported. |
| 2025-10-14 | Rust CodeQL support GA. [S7] | Exclude Rust from the unsupported-language shortlist. |
| 2026-06-10 / 2026-07-14 | Dedicated `/security-review` in Copilot CLI, then the Copilot app, announced as public preview; CLI required experimental mode in its announcement. [S12][S13] | A separate on-demand AI review surface exists; do not confuse it with PR code scanning or named Autofix. |
| 2026-07-14 | AI-powered code-scanning detections entered preview with CodeQL default-setup and Copilot-license prerequisites. [S9] | Those original requirements are historical, not the current contract. |
| 2026-08-07 | Copilot code review **Lite/Balanced** effort levels GA. [S11] | Security-sensitive review is not limited to an old preview or CodeQL language list. |
| 2026-09-16 | AI Scan removed its CodeQL default-setup dependency. [S5] | A PHP-only or HCL-only repository need not add a dummy CodeQL-supported application. |
| 2026-10-15 | AI Scan GA, including public personal/organization repositories; no Copilot license required. [S4] | Native unsupported-language PR detection and conditional named Autofix are viable product capabilities today. |
| 2026-10-15 | **Agentic autofix** GA. [S15] | A second named remediation product must be distinguished from one-step Copilot Autofix and ordinary issue-assigned coding work. |

Current feature-specific documentation takes precedence over older launch prerequisites. There are also documentation seams: the general AI application card chiefly describes CodeQL Autofix, while the AI Scan page explicitly documents Copilot Autofix for AI findings. Similarly, the backlog-resolution page's “only available for backlog alerts” wording must be read in its **backlog Generate fix workflow** context: the separate PR-triage and AI Scan docs explicitly document PR suggestions. Do not extrapolate either sentence into a global prohibition on PR Autofix. [S3][S14][S17][S18]

## 4. Small viable shortlist, without choosing a language

All three candidates are outside the CodeQL language list, are explicitly named by AI Scan, and can receive general Copilot code review. For all three, **AI Scan → named Copilot Autofix is conditional on a supported finding and a generated suggestion**, not an unconditional language-wide fix entitlement. Agent built-in CodeQL coverage is **no** for the candidate files. Secret scanning is language-independent, not evidence that these source files receive semantic SAST. [S1][S3][S6][S10]

| Candidate | Why it is viable to investigate for Azure SRE handover | Native security / dependency / alternative paths | Important limitation |
| --- | --- | --- | --- |
| **PHP** | A real application implementation language with first-party Azure App Service deployment guidance. PHP on App Service is supported on **Linux**, not Windows. [S32] | AI Scan explicitly lists PHP. Composer has dependency graph support (`composer.lock`, also `composer.json`), Dependabot version/security updates, and PR dependency review for recognized dependencies. A separate local Semgrep-to-SARIF path is technically possible; its PHP support and SARIF output are documented by its maintainer. [S3][S26–S29][S35][S36] | No CodeQL PHP analysis. Semgrep paid Pro capabilities are not implied by availability of its local CLI/community rules. Neither Composer alerts nor generic AI patches establish Copilot Autofix eligibility for an application finding. No fixture has yet shown that the incident and a security finding are the same problem. |
| **Shell/Bash** | Plausible operational-script change around Azure CLI; Microsoft documents running Azure CLI in Bash locally and in Cloud Shell. [S33] | AI Scan explicitly lists Shell/Bash; general code review is language-inclusive. Credential scanning can apply. [S3][S10][S30] | This is an operational program, not automatically a web-application implementation. No Bash package ecosystem appears in the dependency graph/Dependabot lists: do not promise advisories/updates for arbitrary `apt`, downloaded binaries or shell-managed dependencies. Semgrep lists Bash as **experimental**, not equivalent to its GA PHP support. [S26][S27][S35] |
| **Terraform HCL** | Plausible infrastructure-code handover; Microsoft's Azure Terraform overview documents Azure providers and plan-before-apply workflows. [S34] | AI Scan explicitly lists HCL. An alternative scanner path can use a locally run IaC scanner with Azure/Terraform checks and SARIF output, such as Checkov. [S3][S37] | Infrastructure configuration is not an unsupported application implementation language. Dependabot supports Terraform **version updates**, but **not security updates** in its current table; Terraform is absent from the dependency graph's native ecosystem table. Provider updates are not proof of vulnerability detection. Checkov/SARIF findings do not acquire guaranteed classic Copilot Autofix; agentic remediation cannot confirm them using CodeQL. [S14][S26][S27] |

**Other boundaries:** Dockerfiles are an explicitly documented AI Scan option, potentially accompanying any application, but do not alone establish that the application's implementation language is covered. PowerShell, Dart, Elixir and Scala must not be presented as AI Scan-supported based on this evidence: CodeQL does not list them and AI Scan's examples do not affirm them. Its examples are not an exhaustive denial list, so this is **unverified**, not a claim that detection is technically impossible. Java/JSP and C#/Blazor demonstrate framework expansion, but do not satisfy a strict requirement to choose an implementation language outside CodeQL. [S1][S3]

## 5. Availability, permission, visibility and trigger preflight

### AI Scan: the decisive non-CodeQL product

| Repository | AI Scan availability | License and billing |
| --- | --- | --- |
| Organization public | Available with code scanning and effective AI Scan enabled | No active-committer license required; **Code Security AI Credits still consumed**. |
| Organization private/internal | Available with effective enablement | GitHub Code Security or GitHub Advanced Security required, plus AI credits. |
| Ordinary personal public | Available; repository admin controls toggle directly | No Copilot license required; AI credits billed to personal account, or the organization/enterprise providing the owner's Copilot license, per current docs. |
| Ordinary personal private | **Not available** | Buying Copilot alone does not change this. |
| Enterprise Managed User personal namespace | **Not available** | Code Security licenses/credits/budgets do not make it eligible. |

These are current documented rules, not assumptions drawn from public-repository CodeQL pricing. Public does **not** mean all AI security functionality is free. Included Copilot AI credits can be used if the billing account has them; otherwise usage is metered. Exhausted hard budgets can prevent findings. [S3][S25]

For paid private/internal security features, GitHub Code Security and GitHub Secret Protection are separate products available to organizations on **GitHub Team or GitHub Enterprise Cloud** (or through applicable GHAS entitlements). A Copilot subscription alone buys neither. Secret Protection alone does not unlock private code scanning/AI Scan; Code Security alone does not provide private repository secret scanning. The cloud agent's license-free built-in validation exception does not unlock the repository-wide products. [S6][S24]

- **Permissions/policy:** enterprise owners allow AI Scan (default policy is **Not allowed**); organization owners/security managers enable it; eligible repositories inherit enablement. Organization repository admins can opt out but cannot opt in against a disabled organization setting. Enabling organization-wide can incur usage immediately. Ordinary personal-public repo admins enable directly. [S3]
- **Trigger:** code scanning enabled + AI Scan enabled + relevant supported changed code + PR **not from a fork and not created by Dependabot**. Runs on PR creation and new commits, independent of CodeQL status/default setup. A pre-existing flaw only on `main` has no AI Scan backlog scan. [S3]
- **Bot/agent nuance:** those rules do not exclude every bot or Copilot-authored same-repository PR; do not misstate the Dependabot exclusion as “all bots.” Conversely, no exercised evidence here establishes exact draft/ready timing for a cloud-agent PR. Record that behavior in a later isolated acceptance test, rather than assuming ordinary Actions approval behavior controls this native engine. [S3][S6]
- **Learner repository topology:** a fork-origin PR back to the workshop repository is ineligible. A learner-owned template/copy with a branch PR inside the same repository avoids that specific exclusion. “From a fork” describes PR origin; do not equate every branch PR within a repository that happens to be a fork with an upstream cross-repository PR.
- **Not customizable like code review:** AI Scan does not use `.github/copilot-instructions.md`/`CLAUDE.md` detection instructions. Agent customization can affect the investigation/coding/review journey without proving it steers this security engine. [S3]

### Coding agent and Copilot review

- Current cloud-agent access docs identify Pro/Pro+/Max as enabled by default and Business/Enterprise as administrator-enabled; current plans also include agent access for Student. Repository policy can opt out. GHAS licensing does not substitute for coding-agent access. Use an explicitly eligible attendee entitlement, enabled policies and available AI budget/Actions capacity. Cloud agent is GitHub-hosted-repository functionality; Copilot is not available on GHES. [S38][S39]
- **Write access** is required to trigger cloud agent. The human assigns work; the agent proposes a branch/PR and cannot approve/merge it or mark its draft ready. Attendee inspection, workflow approval where required, merge, and deployment remain human actions. [S6]
- Actions on cloud-agent PRs require **Approve and run workflows** by default. There is now an administrator opt-out, but it grants unreviewed code access to potentially privileged workflows: its existence is not a recommendation to enable it. This matters for third-party SARIF upload/testing, and must not be confused with the agent's built-in checks. [S6][S19]
- Copilot PR review is available through Pro/Pro+/Max/Business/Enterprise. Copilot Free's VS Code “Review selection” is **not** GitHub PR review access. Organizations on Business/Enterprise can enable **paid** reviews for members without seats via two policies; this is not free universal review. Reviews consume AI credits and agentic context gathering uses Actions resources. [S10][S11][S39]
- Current PR review supports bot-authored PRs, including agentic review; cloud-agent PR review billing is attributed to the human co-author first, otherwise the organization. Older “no bot reviews” assumptions should not be carried forward. Manual requests, eligible personal automatic-review settings, and repository/org rulesets are distinct triggers. Draft and each-new-push reviews require their respective automatic-review settings; otherwise request/re-request explicitly. [S10][S20]
- Authorized-user-only review settings can restrict who can request review. For personal repos with this enabled, requester must be owner/direct collaborator. Enterprise/org Copilot review policies and spending limits may still prevent access. Model switching is not supported for Copilot code review; Lite/Balanced changes effort. [S10]
- **Self-guided does not mean a second required approver:** the person initiating an agent PR cannot supply a required approving review for it. Current rules can require additional approval for unattributed agent PRs. A mandatory independent-approval ruleset can therefore conflict with a solo lab. Later repository setup must respect applicable policies while allowing attendee human inspection/merge; neither automated approval nor silent policy bypass is implied. Copilot approvals are themselves an optional **public preview**, off by default, not necessary to establish the research path. [S6][S10][S20]

### SARIF and alert remediation

- A SARIF upload needs a functioning scanner, supported SARIF, correct source/commit association and appropriately authorized upload. The documented Actions upload example grants `security-events: write`; private-repository upload additionally uses `actions: read` and `contents: read`. REST integrations need the corresponding code-scanning write authorization. Do not assume a read-only token can upload or that `upload-sarif` runs a scanner. [S22][S23]
- Third-party scanning can run locally or on Actions; a SaaS upload is not mandatory. Before adopting one, review its license, telemetry, registry calls and data handling. Semgrep's maintainer explicitly warns that `--config auto` logs the project URL to its registry and documents metrics; do not silently use hosted scanning or transmit private code. No scanner was run for this research. [S21][S36]
- Agentic autofix has separate cascading enterprise/org/repo controls, supports direct enablement in eligible ordinary personal-public repos, excludes EMU personal namespaces, and requires re-enablement if previously used in preview. Users need **write** access to assign alerts. It consumes AI credits and Actions minutes without requiring a Copilot seat. The GA announcement foregrounds Enterprise Cloud customers; the **current access guide** also explicitly documents standalone organizations and eligible personal-public repositories. Do not turn the launch article into an enterprise-only restriction, or assume personal-private eligibility. [S14–S17][S25]
- For classic code-scanning Autofix, administrative disallow settings cascade down. Verify the actual finding shows an offered suggestion; do not infer fix eligibility from an uploaded SARIF record, a language name, or a generic “Generate fix” label in old screenshots. AI Scan PR-only findings cannot be assigned to backlog-only agentic autofix. [S3][S14][S17]

## 6. Can one reproducible journey exercise all of this?

**Capability-level answer: conditionally yes. Reliability-level answer: not yet established.** A same-repository PHP, Bash or HCL PR can receive Copilot code review, native AI Scan findings, and an offered **Copilot Autofix** suggestion in one change journey. The sources establish that combination as eligible, not that any chosen incident/change will produce all three outputs on demand. [S3][S10]

Important feasibility constraints, not final design choices:

1. **Detection needs the right changed code.** If the incident is an existing `main` bug and the coding agent's PR only removes it, PR-only AI Scan may have no remaining issue to report. If the agent fixes its own issue during built-in validation/review, no later visible review finding is guaranteed. A single functional incident is not automatically a security finding. [S3][S6]
2. **No guaranteed AI finding or Autofix.** False positives/missed findings are possible; most findings have remediation, not all have code suggestions. Success criteria cannot honestly require a specific named suggestion on every learner run without later repeatability evidence and a disclosed fallback. [S3][S17][S18]
3. **No CodeQL equivalent in disguise.** AI Scan is advisory PR prevention, not full-repository semantic CodeQL, a required blocking security check, or default-branch backlog/campaign material. Its finding cannot be handed straight to backlog-only agentic autofix. [S3][S14][S17]
4. **No guaranteed solo-enterprise setup.** A personal-public copy is supported but consumes AI credits and exposes its contents; organization-private can preserve privacy but needs paid security products and appropriate administrative policy. Personal-private cannot deliver the native AI Scan leg. Publicizing a private project is not an acceptable workaround. [S3][S25]

Honest alternative paths if the exact combination cannot be made repeatable:

| Alternative | Preserves | Gives up / must be disclosed |
| --- | --- | --- |
| Selected deterministic PHP/IaC scanner, pinned rules and version, local/Actions SARIF → code review → issue/PR-assigned coding-agent fix | Reproducible scanner finding and rescan evidence; GitHub-native alert presentation; unsupported implementation/config language can remain. [S21–S23][S35–S37] | Generic coding-agent remediation is **not classic Copilot Autofix**. Tool licensing/coverage/data handling must be checked. Separate backlog agentic autofix can attempt a third-party alert but cannot validate it with CodeQL. [S14] |
| PHP Composer dependency review/Dependabot + Copilot review/coding-agent handover | Known-advisory detection and, when available, a dependency-update PR; public/private ordinary Dependabot availability. [S24][S26–S29] | Exercises dependency remediation, not application-code SAST or named Copilot Autofix. A Dependabot-authored PR is excluded from AI Scan. |
| Optional AI Scan/Copilot Autofix observation beside a deterministic acceptance gate | Demonstrates current native capability without making AI output the sole pass/fail condition. [S3] | Named Autofix appearance remains conditional; a manual/agent fallback must be labeled honestly. This is a feasibility trade-off, not a selected workshop design. |
| Supported-language code or a supported-language auxiliary component with CodeQL | Established CodeQL detection and supported-query Autofix eligibility. [S1][S18] | Changes/weakens the “security detection in the non-CodeQL implementation language” objective; scanning Actions YAML or a JS sidecar is not evidence that PHP/HCL received CodeQL coverage. |

Before any later language/design decision, a bounded acceptance test should establish repository/billing eligibility, exact PR origins and draft behavior, repeated finding/suggestion appearance, how the finding relates to the incident, actual scanner/agent validation logs, single-attendee merge feasibility, and a reset/fallback route. **That experiment was not authorized or performed here.** No final language, security example, workflow, deployment architecture, or scenario design is selected by this research.
